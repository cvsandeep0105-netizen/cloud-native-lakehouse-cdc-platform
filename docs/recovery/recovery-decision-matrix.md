# Recovery Decision Matrix\n\n## Decision Rule\n\nRecovery action is selected only after the failure is detected and classified. An unsuccessful processing attempt never advances the authoritative checkpoint.\n\n| ID | Failure | Recovery Action | Checkpoint Advance During Failure | Decision / Escalation |\n|---|---|---|---|---|\n| F01 | Transient Infrastructure | RETRY | No | Retry within approved policy |\n| F02 | Source Availability | RETRY_OR_BLOCK | No | Retry, then block and escalate |\n| F03 | CDC Capture Failure | RESTART_OR_REPLAY | No | Restart capture or replay from authoritative position |\n| F04 | CDC Ordering Failure | BLOCK | No | Reject invalid ordering and require review |\n| F05 | Duplicate CDC Event | DEDUPLICATE | No | Apply deterministic event identity |\n| F06 | Checkpoint Commit Failure | RETRY_COMMIT | No | Retry checkpoint commit without advancing boundary prematurely |\n| F07 | Incremental Processing Failure | RESTART_FROM_CHECKPOINT | No | Restart from last committed checkpoint |\n| F08 | Schema Compatibility Failure | BLOCK | No | Stop processing and require schema review |\n| F09 | Data Quality Failure | QUARANTINE_OR_CORRECT | No | Quarantine or correct according to approved DQ controls |\n| F10 | Reconciliation Failure | BLOCK | No | Stop downstream publication and investigate discrepancy |\n| F11 | Silver Processing Failure | RESTART_OR_REPLAY | No | Restart or replay from validated checkpoint |\n| F12 | Gold Product Failure | REPROCESS_AFTER_VALIDATION | No | Reprocess from validated Silver state |\n| F13 | Metadata/Lineage Failure | BLOCK_AND_REVALIDATE | No | Block dependent publication and revalidate metadata |\n| F14 | Data Integrity/Corruption | ISOLATE_AND_INVESTIGATE | No | Isolate affected data and require human review |\n\n## Recovery Precedence\n\n1. Preserve the last committed checkpoint.\n2. Isolate the failing component.\n3. Retry only when the failure is classified as retryable.\n4. Restart from the committed checkpoint when processing failed before checkpoint advancement.\n5. Replay or backfill only within deterministic boundaries.\n6. Block downstream stages when an upstream blocking failure remains unresolved.\n7. Require human review for unresolved, breaking, integrity, DQ, and reconciliation failures.\n\n## Control Authority\n\nCDC ordering, deduplication, idempotency, checkpoint, DQ, reconciliation, schema, metadata, and lineage controls remain authoritative over recovery actions.\n\n## AWS Boundary\n\nAWS-native recovery implementation is a future deployment concern. AWS recovery execution is not claimed by this Area.\n
