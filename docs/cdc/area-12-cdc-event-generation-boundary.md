# Area 12 — CDC Event Generation / Capture

## Purpose
Define how Project 02 generates and captures change events without confusing CDC simulation with genuine source CDC.

## Source Truth Boundary
- The Olist Brazilian E-Commerce dataset is static historical data.
- Olist does not provide a native historical CDC stream.
- Any historical Olist change stream generated by this project is explicitly CDC simulation/replay.

## Genuine Local CDC
- PostgreSQL logical replication is enabled on the operational source.
- Native PostgreSQL WAL changes can be captured through logical decoding.
- Genuine local CDC evidence must come from an actual PostgreSQL source change and logical-decoding capture.

## AWS Boundary
- AWS DMS is an evaluated CDC architecture candidate.
- AWS DMS execution is not claimed unless independently executed and evidenced.

## Area 12 Scope
- Generate controlled source changes.
- Capture the resulting CDC events.
- Preserve the original source-of-change context.
- Record evidence of INSERT, UPDATE, and DELETE operations.
- Establish a reusable capture foundation for later CDC processing.

## Deferred Areas
- Event ordering and sequencing: Area 13.
- Deduplication and idempotency: Area 14.
- Replay, late events, and backfill: Area 15.

## Claim Integrity
All evidence must distinguish designed, simulated, locally verified, and AWS-executed behavior.
